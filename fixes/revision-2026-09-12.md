## Problemas y límites pendientes

1. **Alta — Auth0 impide ejecutar las propuestas (F-06).** Reproducido en el
   ensayo: el token no satisface `write:workspace`. El rechazo en
   `packages/loop-core/src/boundary/auth0.ts:58` es correcto; no hay que quitarlo
   ni activar un bypass para presentar la integración como verificada. R2 debe
   configurar los permisos de la API y de la aplicación M2M; después repetir el
   ensayo. Esta corrida no llegó a verificar `send:channel` ni `schedule:job`.

2. **Alta — Slack no puede arrancar con este entorno (F-06).** Faltan
   `INTELLIGENCE_API_KEY` y `CHANNEL_CODE`, requeridas por
   `apps/channel/src/server.ts:19` y `silentops-channel.tsx:71`. R3 debe completar
   el setup. Los tests del gateway son simulados y no prueban una entrega real.

3. **Media — El ensayo acepta documentos ajenos a la ausencia detectada.** En
   `packages/loop-core/scripts/rehearse-e2e.ts:159` un título distinto solo genera
   un aviso; en la línea 173 se permite más de un handover. Una propuesta con uno
   correcto y otro ajeno puede aprobarse y superar la comprobación posterior del
   documento esperado. La limpieza intenta purgar ambos por ID, pero si falla
   puede dejar contaminación evitable. R2: exigir título igual a `expectedTitle`
   y exactamente un handover antes de aprobar; reasignaciones y aviso pueden
   conservar su validación independiente. Hallazgo de revisión estática, sin
   ejecutar escrituras reales para reproducirlo.

4. **Media — La limpieza puede revertir cambios de otra persona.**
   `packages/loop-core/scripts/rehearse-e2e.ts:201` compara y restaura todas las
   tasks del snapshot, aunque el ensayo no haya tocado algunas. Si el equipo
   edita una task durante el ensayo, ese cambio también puede restaurarse al
   valor anterior. R2: limitar restauraciones a las tasks modificadas por esta
   corrida y comprobar que su estado actual coincide con el resultado del
   ensayo antes de sobrescribirlo. Mientras tanto, el modo real necesita un
   workspace sin ediciones concurrentes. No se ejecutó ese modo en esta revisión.

5. **Media — El cuerpo libre del handover omite el filtro de fuentes.**
   `packages/loop-core/src/boundary/ambiguous-writer.ts:147` prefiere `args.content`
   al Markdown generado a partir de bullets filtrados y limitados a cinco. Un
   payload con `content` puede incluir hechos sin las fuentes exigidas para los
   bullets. Sigue requiriendo aprobación humana; el problema es la garantía de
   trazabilidad del contenido. R2: eliminar ese atajo para la intención de
   handover o aplicarle una validación equivalente.

6. **Media — Idempotencia con ventana de duplicación (F-07).** En
   `packages/loop-core/src/boundary/write.ts:77` se consulta la clave, luego se
   ejecuta la acción y recién en la línea 84 se registra el resultado. Una caída
   entre escritura y registro, o aprobaciones concurrentes, puede duplicar una
   acción. El reenvío secuencial ya completado está cubierto por tests. R2:
   registrar intención antes de escribir, serializar por clave y reconciliar
   resultados inciertos con el proveedor.

7. **Media — El golden set verde no valida todavía el camino real (F-18 parcial).**

14. **Alta — Después de un fallo la interfaz pierde el camino de reintento.**

    considera viva y no publica una nueva card. El boundary sí soporta reintentar,
    pero esta interfaz no lo expone. R2/R3: añadir una acción explícita de
    reintento sobre la misma propuesta, manteniendo el gate de riesgo alto y
    mostrando cuáles acciones ya se ejecutaron. Probar un fallo parcial y el
    reintento desde el gateway. La confirmación adicional de riesgo alto ya
